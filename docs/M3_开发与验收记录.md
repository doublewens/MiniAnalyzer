# MiniAnalyzer v0.4-M1M2M3：M3开发与验收记录

## 开发内容

从已交付、可运行的M1/M2教学预览版直接演进，仅新增M3：

- `analyzer/analysis/reaching_definitions.py`：前向 may 可达定义参考实现；保持v0.3的DataflowAnalysis六个核心接口。
- CLI `--analysis rd`：与原 `ir|cfg|live` 共存；M2文本和JSONL跟踪同时可用于`rd`。
- 三份IR示例：分支汇合、循环回边、连续覆盖/调用。
- 数学语义与GEN/KILL案例推导、15分钟教师演示指导、M3接口契约。
- 8项新增测试，包含手工期望结果、固定点方程、transfer纯函数行为、trace一致性和CLI输出分流。

## 测试结果（本次执行）

- `python -m pytest -q`：**21项通过**（包括13项原M1/M2测试）。
- 使用原M1/M2 ZIP解压到独立目录，在`assign|branch|live|live_loop|loop`五个旧输入与`ir|cfg|live`三种旧命令上逐组比较JSON，**15/15完全一致**。
- 分支例子节点7：`IN[7]={c@1,x@4,x@6}`；旧定义`x@2`不会到达汇合点。
- 循环例子节点3：`IN[3]={x@1,x@4,y@2}`，节点4的`OUT={x@4,y@2}`；工作队列收敛。
- `rd`跟踪打开与关闭时，结果JSON及求解统计一致。

## 说明与边界

这不是正式的v0.4完整版本。M4“教师Reference/学生Student实现并存、算法注册与对比”尚未开发。
本版保留指令级CFG与全CFG节点调度的旧行为，不支持Mini-C、过程间/内存别名等真实程序语言特征；可达定义只考虑显式变量赋值。`iterations`是节点处理次数，不是整个CFG完成扫描的轮数。

下一阶段：设计/实现M4，实现算法注册、教师/学生双实现、自动对比及带TODO的学生实验模板。建议先冻结本版语义与样例，再扩展M4。
